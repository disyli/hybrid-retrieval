MODULE 01

分词器 tokenize.py

25 行 · 纯标准库全链路唯一入口

中文不依赖分词库：单字 + 相邻双字（bigram），英文按字母数字串。是 BM25 与哈希嵌入共用的一致词元空间。

运行机制

  1. 统一小写：text.lower()，让 "Hybrid" 与 "hybrid" 落入同一词元。
  2. 正则切出中文连续段：_CJK 匹配 \u4e00-\u9fff 连续汉字；段与段之间的非中文部分交给 _ALNUM 抓英文/数字串。
  3. 中文段双份产出：每个汉字出一个 unigram，每个相邻汉字对出一个 bigram —— "混合检索" 产出 4 个单字 + 3 个双字。
  4. 保留重复：返回带重复的 list 而非 set，因为下游 BM25 需要统计词频 TF。
为什么 bigram 近似词义："混合检索" 无论被正确切成"混合/检索"还是错误切成"合检"，bigram 集合都高度重叠 —— 用冗余换鲁棒，永不切错。
tokenize.py · 核心 12 行
def tokenize(text: str) -> list[str]:
    text = text.lower()
    tokens, pos = [], 0
    for match in _CJK.finditer(text):          # 中文连续段
        if match.start() > pos:
            tokens.extend(_ALNUM.findall(text[pos:match.start()]))
        run = match.group()
        tokens.extend(run)                            # 单字 unigram
        tokens.extend(run[i:i+2] for i in range(len(run)-1))  # 双字 bigram
        pos = match.end()
    return tokens  # 带重复，供 BM25 计词频

MODULE 02

词法检索 bm25.py

36 行 · 纯标准库

标准 Okapi BM25：词越稀有越值钱（IDF），词频收益递减（TF 饱和），长文档打折（长度归一）。

运行机制 · 构造期（离线一次）

  1. 对每篇已分词文档建 Counter 词频表，记录 doc_len 与全库平均长度 avgdl。
  2. 汇总每词的文档频率 df，预计算 IDF：一个词出现在越少的文档里，权重越高。

运行机制 · 打分期（每查询）

  1. 对查询的每个词元：词不在文档中直接跳过；在则累加一项 IDF × 饱和TF × 查询词频qtf。
  2. TF 项分子含 (k1+1)、分母含 tf + k1·(...) —— tf 再大，单项得分也被封顶在 IDF·(k1+1) 附近。
  3. 分母中的 b 控制长度惩罚：文档比平均越长，分母越大，得分越被稀释。
IDF(t) = ln N − df(t) + 0.5df(t) + 0.5 + 1 IDF · 稀有词高权重
score(D,Q) = Σt∈Q IDF(t) · tf(t,D) · (k1+1)tf(t,D) + k1·(1 − b + b·|D|/avgdl) · qtf(t) Okapi BM25 · k₁=1.5, b=0.75
bm25.py · 打分循环
score = 0.0
for term, qtf in qfreq.items():
    if term not in df:          # 查询词不在文档 → 跳过
        continue
    tf = df[term]
    denom = tf + self.k1 * (1 - self.b + self.b * dl / self.avgdl)
    score += self.idf[term] * tf * (self.k1 + 1) / denom * qtf
三个直觉：IDF 管"什么词重要"，k₁ 管"重复出现还值不值钱"，b 管"长文档是否注水"。
MODULE 03

文本嵌入器 embedder.py

默认 · SentenceTransformer 语义向量兜底 · HashEmbedder

统一接口 embed(text) → list[float]。语义版理解"意思相近"，哈希版只看"字面重叠"—— 同一插槽的两种实现。

SentenceTransformerEmbedder（默认）

  1. 构造时懒加载 sentence-transformers，模型 paraphrase-multilingual-MiniLM-L12-v2（12 层 MiniLM，多语言含中文）。
  2. 文本过 Transformer 编码器，token 向量做 mean pooling 得句向量，输出前 归一化。
  3. 得到 384 维单位向量：余弦相似度退化为点积；"怎么合并两路结果" 与 "RRF 融合" 这种零词面重叠的同义对，距离也会很近。

HashEmbedder（兜底）

  1. 复用 tokenize() 词元，每个词 sha256 后 % 512 落入固定槽位。
  2. 槽位累加 1 + ln(count) —— 子线性词频，防高频词霸占向量。
  3. L2 归一化后输出。本质是词袋的哈希投影：确定性、零依赖，但只有词法没有语义。
embedder.py · 两种实现
# 语义版：真·理解意思（默认）
class SentenceTransformerEmbedder:
    def embed(self, text):
        return self._model.encode(text,
            normalize_embeddings=True).tolist()  # 384 维

# 兜底版：字面哈希词袋
class HashEmbedder:
    def embed(self, text):
        vec = [0.0] * self.dim
        for term, count in Counter(tokenize(text)).items():
            idx = _hash_token(term, self.dim)      # sha256 % 512
            vec[idx] += 1.0 + math.log(count)     # 子线性 TF
        return [v / norm for v in vec]     # L2 归一化

def make_embedder(prefer_semantic=True):
    try:    return SentenceTransformerEmbedder()  # 默认
    except Exception: pass
    return HashEmbedder()                      # 静默回退

MODULE 04

向量索引 vector_index.py

默认 · FaissIndex兜底 · FlatIndex

统一接口 search(query, k) → [(下标, 分数)]。兜底版纯 Python 暴力扫全库，Faiss 版仍是精确检索、只是用矩阵运算加速。

FlatIndex · 兜底

  1. 存住全部向量，查询时对每个向量逐一算 cosine()。
  2. 全量排序取 top-k。复杂度 O(N·d) —— 17 篇文档毫秒级，百万篇就不可用。

FaissIndex · 默认

  1. 构造期把向量堆成 float32 矩阵，faiss.normalize_L2 原地归一化。
  2. 建 IndexFlatIP（内积索引）并 add 全库。归一化后内积 ≡ 余弦，这是全套三角换算的关键一步。
  3. 查询向量同样归一化后 search，底层是 BLAS/SIMD 批量矩阵乘，比 Python 循环快几个数量级。
注意：IndexFlat 仍是"精确"近邻（无近似损失）。工业界百万级会换 IVF / HNSW 索引，用少量召回率换速度 —— 本仓库刻意保持精确，教学优先。
cos(a, b) = a · b|a| · |b| — 归一化后 — a · b 余弦 → 点积的降维打击
vector_index.py · Faiss 路径
matrix = np.asarray(vectors, dtype="float32")
faiss.normalize_L2(matrix)              # 单位向量
self._index = faiss.IndexFlatIP(matrix.shape[1])  # 内积索引
self._index.add(matrix)

def search(self, query, k):
    q = np.asarray([query], dtype="float32")
    faiss.normalize_L2(q)               # 查询同样归一化
    distances, indices = self._index.search(q, k)
    return list(zip(indices[0].tolist(), distances[0].tolist()))

MODULE 05

融合检索器 retriever.py

系统总指挥

两条召回支路 + RRF 排名融合 + 喂给重排器。HybridRetriever 是把前 4 个模块串成流水线的 orchestrator。

构造期（离线建库）

  1. 每篇文档 title + " " + text 拼接 → tokenize → 建 BM25 索引。
  2. 同一份拼接文本 → embedder.embed → make_index 建向量索引。两路索引共享同一原文，只是"视图"不同。

检索期（在线，每查询）

  1. 双路召回：BM25 全量打分取前 k=min(20, N)；向量索引搜前 k。注意只取 20 个候选 —— 粗排求"别漏"，不求"排准"。
  2. RRF 融合：每路内部按排名 1..k 产生 1/(60+rank) 分；两路都命中的文档分数相加，天然把"双路共识"顶到最前。
  3. 交给重排器：reranker.rerank(query, candidates, rrf_scores) 精排，最后切 top_k 返回。
为什么用排名不用分数：BM25 分数可以是 8.7，余弦是 0.83，量纲完全不可比；而"排名第 1"在两边是同一种语言。RRF 只消费排名，天然免疫量纲。
RRF(d) = Σ支路 i 1krrf + ranki(d) ,  krrf = 60 Reciprocal Rank Fusion
retriever.py · retrieve() 融合段
bm25 = self._bm25_scores(query)

    self.embedder.embed(query), k)             # 语义 top-20

for rank, (idx, _) in enumerate(vec_hits, start=1):

MODULE 06

重排器 reranker.py

默认 · CrossEncoder bge-reranker-base兜底 · RuleReranker

粗排只保证"前 20 里有答案"，精排负责"把答案顶到前 3"。统一接口 rerank(query, candidates, scores)。

RuleReranker · 兜底

  1. 查询词元集合 ∩ 标题词元集合 非空 → RRF 分数 +0.1，否则原分。
  2. 教学彩蛋：0.1 > RRF 分数量级（≈0.016~0.033），所以标题命中几乎一票决定排序 —— 简单粗暴，但免费、可解释。

CrossEncoderReranker · 默认

  1. 把 (query, title + text[:400]) 拼成 pair —— 文本截断 400 字控延迟，模型侧 max_length=512。
  2. 交叉编码：query 与 doc 在同一个 Transformer 里逐 token 互相 attention，直接输出相关性分 —— 这正是双塔结构做不到的"深交互"。
  3. predict(pairs) 批量打分后重排序。贵但准，所以只用在 20 个候选上：粗排管快，精排管准。
双塔 vs 交叉编码器：双塔（嵌入模型）query/doc 各自编码、可预建索引、快而浅；交叉编码器逐对联合编码、无法预建、慢而深 —— 这就是"先召回后重排"两阶段结构的根本原因。

RAG 生成器 rag.py

配置 key → LLM 带引用生成未配 key → retrieval_only

把 top-k 片段变成"有据可查"的答案。纯标准库 urllib 直连 OpenAI 兼容接口，无 SDK 依赖。

运行机制

  1. 构造时读环境变量：LLM_API_KEY（兼容 OPENAI_API_KEY）、LLM_BASE_URL（默认 OpenAI，可指向任意兼容网关）、LLM_MODEL（默认 gpt-4o-mini）。
  2. top-k 文档拼成带编号资料：[1] 标题\n正文 …；system 提示要求"只能引用资料内容，句末标注来源编号"。
  3. temperature=0 压随机性，POST /chat/completions，解析 choices[0].message.content。
  4. 返回三元组：status / answer（含 [1][2] 标注）/ sources（id+标题+摘要，用于前端溯源跳转）。
诚实降级：没配 key 时不假装生成，status="retrieval_only" 直接返回编号片段拼接 —— 调用方一看 status 就知道这是检索不是编造。

离线评估 evaluate.py

61 行 · 标注驱动

检索系统的"期末考试"：在标注查询集上对比 bm25 / vector / hybrid 三种模式，量化"找全"与"排准"。

运行机制

  1. 读 data/queries.jsonl：每行一个 query + 人工标注的相关文档 id 集 relevant。
  2. 三种模式分别取 top-5：bm25 用 _bm25_scores 单路排序；vector 用 _vector_scores；hybrid 走完整 retrieve()（含重排）。
  3. 每条查询算 recall@5 与 MRR，最后对 16 条查询取平均，打印三行对照表。
recall@k = |hitsk ∩ relevant||relevant|   ·   MRR = 1rank(首个相关文档) 找全了吗 · 排准了吗
evaluate.py · 两个指标
def recall_at_k(hits, relevant, k):
    return sum(1 for h in hits[:k] if h in relevant) / len(relevant)

def mrr(hits, relevant):
    for rank, h in enumerate(hits, start=1):
        if h in relevant:
            return 1.0 / rank      # 只看第一个相关的位置
    return 0.0
