构造期公式 图解

BM25 分两阶段：构造期把所有"查询无关"的统计量一次算好，查询期只做查表累加。本页用同一份 3 篇文档的迷你语料，把构造期 6 个公式逐个"画"出来：每条公式都配代入计算和可视化。

00

先看全局：钱花在哪一次？

构造期 = 索引一次，查询期 = 便宜 N 次。下面所有公式都是为了让右边的绿框"只查表、不计算"。

📍 构造期 __init__
输入: docs(词元列表)
遍历语料一次，产出 5 件产物
N · doc_len · avgdl · doc_freqs · idf
⚡ 查询期 score()
输入: query + doc_idx
O(查询词数) 查表累加
构造期产物直接复用

公式 1–3：N、doc_len、avgdl

先量"地有多大"：语料几篇、每篇多长、平均多长。

N = |D| = 3 公式1 · 语料规模（文档篇数）
doc_len(d) = |tokens(d)| 公式2 · 单篇长度：词元个数（含重复）
avgdl = 3+2+23 = 2.33 公式3 · 平均文档长度（防除零用 max(1,N)）

注意"含重复"：["检索","检索"] 的长度是 2，不是去重后的 1。avgdl 现在看似没用，它是查询期长度归一化的基准尺，必须构造期备好。

公式 4：词频 tf(t, d) = Counter

每篇文档建一个正排计数器：这个词在这篇里出现几次。

doc_freqs[d] = Counter(tokens(d))　→　tf(t, d) = t 在 d 中的出现次数 公式4 · 每篇一个 Counter（正排，非倒排）

实现要点：Counter(d) 保留重复计数；查询期若 term not in df 直接 continue，贡献 0 分。库小时正排够用，生产系统会换成倒排（term → 文档列表）。

04

公式 5：文档频率 n(t) = 出现矩阵行求和

把每篇文档的 Counter 只喂 keys()（去重）再累加：统计"出现过该词的篇数"，每篇最多计 1。

词元 tD0D1D2n(t) 篇数直观感受
检索✓✓✓3 = N人手一份，毫无区分度
混合✓·✓2过半文档都有
向量✓··1独有，强信号
学习·✓·1独有，强信号

代码只有两行：for freq in doc_freqs: df.update(freq.keys())。若误喂 freq（含次数），"检索"会算成 1+1+1 之外的更大值——那成了"总出现次数"，IDF 语义就错了。

05

公式 6：平滑 IDF（构造期的主角）

一个词"越稀有越值钱"。三处小机关：±0.5 伪计数、log 内 +1、自然对数。

idf(t) = ln ( N − n(t) + 0.5 n(t) + 0.5 ) + 1 RSJ 伪计数（±0.5）· Lucene 修正（+1）· 自然对数 ln
不含 t 的篇数（越多越稀有） 含 t 的篇数（越多越大众） 防负分修正

代入计算（N = 3）

向量（n=1）：ln( (3−1+0.5)/(1+0.5) + 1 ) = ln(2.667) = 0.981
混合（n=2）：ln( 1.5/2.5 + 1 ) = ln(1.600) = 0.470
检索（n=3）：ln( 0.5/3.5 + 1 ) = ln(1.143) = 0.134

规律：n(t) 越大 → idf 越小。“检索”人人都有，只配拿 0.134 分的权重；“向量”是 D0 独有信号，权重是它的 7 倍。

06

收尾：构造期产物在查询期的位置

看懂这张"消费地图"，构造期 6 个公式就全部闭环了。彩色部分全部来自构造期，查询期只做查表。

score(q, d) = Σt∈q qtf(t) · idf(t) · tf(t,d) · (k1+1) tf(t,d) + k1·(1 − b + b · |D_d| / avgdl) k1=1.5 词频饱和 · b=0.75 长度归一强度（均在查询期生效）
idf：构造期字典查表 tf：构造期 Counter 查表 doc_len / avgdl：构造期备好的长度尺
构造期产物类型查询期消费方式
n_docsintidf 公式的 N（仅构造期用）
doc_lenlist[int]分母中的 |D_d|，做长度归一
avgdlfloat长度归一化的基准尺
doc_freqslist[Counter]查 tf(t,d)；词不在则跳过
idfdict[str,float]每个命中词的权重，直接相乘

一句话总结：构造期把 O(全库) 的统计成本付一次，查询期每次只付 O(查询词数 × 查表)。k1 管"词出现第 10 次还值不值钱"（饱和），b 管"长文档该不该打折"，它们在构造期只是被存起来。
