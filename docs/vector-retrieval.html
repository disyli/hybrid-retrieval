向量检索 语义图解

BM25 只认"字面"，向量检索把文本压成一个高维语义坐标：意思近的文档在空间里挨得近。查询不再翻账本对词，而是问"谁离我最近"。本页延续同一份 3 篇迷你语料，对照 embedder.py 与 vector_index.py 真实实现，把构造期、查询期一次画清。

00

向量检索在链路中的位置

与 BM25 并行跑同一查询，各自给出候选，RRF 融合后进重排器。两侧对称，只是"打分依据"完全不同。

与 BM25 的本质分工：BM25 回答"哪些文档含有这些词"（字面证据），向量回答"哪些文档意思接近"（语义证据）。一个词都不重合也能被向量召回。

01

核心思想：语义 = 空间中的方向

嵌入模型把每段文本映射成高维空间（本库 512 维或 384 维）里的一个点。真实维度画不出来，示意图降到 2 维，机制完全一致。

三句话读懂图

① 每篇文档、每个查询都被压成从原点出发的一个方向。方向由语义决定：讲"检索"的文档挤在同一个扇区。

② 相似度不看距离看夹角（余弦）。夹角小 → 方向几乎相同 → 语义接近。D0 与查询只差 8°，是最相关的文档。

③ 与主题无关的文本方向近似垂直（正交），cos≈0，天然沉底——不需要"排除词表"，语义空间自己完成了过滤。

为什么用余弦不用欧氏距离：嵌入向量的"长度"受文本长度、词频影响，而"方向"才承载语义。余弦只看方向，天然免疫长度差异。

02

嵌入器：embedder.py 的两种实现

统一接口 embed(text) → list[float]。默认优先真语义模型，装不上自动回退到零依赖哈希方案——两种都先归一化再返回。

🧠 SentenceTransformerEmbedder（首选）
paraphrase-multilingual-MiniLM-L12-v2 · 384 维 · 懒加载
  • Transformer 编码器读过海量语料，懂同义、上下文
  • 「电脑坏了」和「笔记本故障」方向几乎重合
  • normalize_embeddings=True 出厂即单位向量
  • 代价：依赖 torch，首次需下载模型权重
🎲 HashEmbedder（回退）
字符 n-gram 哈希 · 512 维 · 零依赖可复现
  • tokenize 切词 → Counter 计数
  • 每个词 sha256 哈希到 512 维中的某一格
  • 该格累加 1 + log(count)，再整体 L2 归一化
  • 仍是"字面相似"：好处是离线可复现、确定性强
同一词的多次出现落在同一格 → 值升高（琥珀格）
def make_embedder(prefer_semantic=True): if prefer_semantic: try: return SentenceTransformerEmbedder() except Exception: pass # 没装 torch/网络不通 → 静默降级 return HashEmbedder() # 保证任何环境都能跑通

教学库的取舍：接口稳定优先。上层 HybridRetriever 完全不感知背后是哪种嵌入器，只依赖"归一化向量"这一契约——这也是生产系统的常见分层方式。

03

打分公式：余弦相似度

向量检索唯一用到的"数学"。分子是点积（逐维相乘再求和），分母是两个模长的乘积——把长度除掉，只剩方向夹角。

cos(q, d) = Σi qi · di‖q‖ · ‖d‖ = q · d‖q‖‖d‖ 值域 [-1, 1]；文本嵌入通常落在 [0, 1]；越大越相似

归一化的魔法

先把每个向量除以自己的模长（‖v‖→1）：
q̂ = q / ‖q‖, d̂ = d / ‖d‖

则　cos(q, d) = q̂ · d̂ （纯点积！）

‖q‖=‖d‖=1 时分母恒为 1，
点积 = 余弦

为什么这是工程关键

点积是矩阵乘法，SIMD/GPU 极致优化过；除法（算模长）却很贵。所以整个链路构造期归一化一次，查询期只做点积：

  • 本库 embed() 返回前就除以 norm
  • faiss 侧再兜底 faiss.normalize_L2(matrix)
  • 索引名直接叫 IndexFlatIP（IP = Inner Product 内积）
04

vector_index.py 逐行拆解

FlatIndex 是最透明的实现：查询期对每篇文档算一次余弦，排序取前 k。高亮行是打分核心。

class FlatIndex: def __init__(self, vectors): self.vectors = vectors # 构造期：整矩阵原样存 def search(self, query, k): scored = [(i, cosine(query, v)) for i, v in enumerate(self.vectors)] scored.sort(key=lambda x: x[1], reverse=True) return scored[:k]
# FaissIndex 对照（懒加载 faiss） matrix = np.asarray(vectors, dtype="float32") faiss.normalize_L2(matrix) # 归一化兜底 self._index = faiss.IndexFlatIP(dim) # 内积索引 self._index.add(matrix) # 构造期入索引 distances, indices = self._index.search(q, k)

两版实现，一个契约

FlatIndex（默认）
纯 Python 列表推导：N 篇文档 N 次 cosine，每次 O(d)。结果精确无近似，适合几千篇以内的教学/小规模场景。
FaissIndex（加速）
float32 矩阵 + C++ 批量点积。注意它二次归一化（第 05 节）：向量已在 embed 层归一化过，这里再 normalize_L2 一次是防御式编程，幂等无害。

make_index(vectors, backend="auto")：auto 先试 faiss，ImportError 就退回 flat——和 make_embedder 同款降级哲学，整库无强依赖。

06

对决 BM25：各赢一局，所以混合

两个典型查询，直观展示两种检索的互补性——以及 RRF 如何把双方证据合起来。

🟣 向量赢：查询「笔记本电脑开不了机」
文档写的是「手提电脑无法启动的排查步骤」
BM25：字面零重合 → idf 贡献 0 → 召回失败
向量：「笔记本电脑」≈「手提电脑」方向几乎重合 → cos≈0.85 高分召回
🟡 BM25 赢：查询「报错 ERR_CONN_1042」
文档含精确错误码「ERR_CONN_1042 排障指南」
向量：错误码被压进 384 维后近似"一串乱码"，区分度低 → 可能排不进前 k
BM25：稀有词 idf 极高、字面精确命中 → 稳居第一

RRF 把两份名次合账（rrf_k=60，沿用第 05 节结果）

文档BM25 名次分向量名次分RRF 总分融合后名次
D01/(60+1) = 0.01641/(60+1) = 0.01640.03281
D21/(60+3) = 0.01591/(60+2) = 0.01610.03202（并列）

07

规模化：暴力检索之后的世界

本库 FlatIndex 是 O(N·d) 暴力扫全库，精确但线性。千万级语料必须换 ANN（近似最近邻），用一点召回率换数量级的速度。

方案复杂度精确?适用
Flat（本库默认）O(N·d)精确教学 / ≤1万篇
IndexFlatIP + faissO(N·d) 但常数极小精确十万级
IVF 倒排文件O(√N·d) 级近似百万级
HNSW 图索引O(logN·d) 级近似千万级·高召回

工程要点

  • ANN 索引（HNSW/IVF）都要求先归一化再建库，否则内积≠余弦，语义就错了
  • 嵌入模型不可中途更换：查询向量必须和库内向量同源同维
  • 删除/更新文档 = 重建或标记 tombstone，比 BM25 倒排的增量更新麻烦
  • 维度越高点积越慢：384 维是速度/效果折中的甜点区

记忆锚点：BM25 的账本加一篇文档只多一行账；向量索引是几何结构，动了空间里的点就可能要重建——这是两种检索在工程维护性上的根本差异。
