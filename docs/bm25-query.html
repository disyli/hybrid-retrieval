01

查账前先看清：三本账长什么样

score() 全部的输入来源。左边两本是"每篇一份"的正排账本，右边一本是全语料共享的"词身份证册"。

📏
① 长度账 doc_len
一个 list，每篇文档记一个数：词元总数（含重复）。查询期用来算"这篇相对平均是长是短"。
[3, 2, 2] # D0,D1,D2 avgdl = 7/3 ≈ 2.33（基准尺）
📒
② 词频账 doc_freqs
每篇文档一个 Counter（字典）：词元 → 出现次数。查一个词就是翻到那一页看计数。
D0: {向量:1, 检索:1, 混合:1} D1: {检索:1, 学习:1} D2: {混合:1, 检索:1}
🪪
③ 身份证册 idf
全语料一本字典：词元 → 稀有度分。越少见的词分越高，构造期算好，查询期只查不改。
向量: 0.981 学习: 0.981 混合: 0.470 检索: 0.134 # 人手一份的"检索"最不值钱

记忆锚点：身份证册回答"这个词多值钱"，词频账回答"这个词在这篇出现了几次"，长度账回答"这篇该打折还是加成"。

02

score() 逐行拆解：每一行都是查表

真实源码 bm25.py 原样贴出，高亮行 = 查账动作。全函数没有循环扫语料，只有字典/列表取值。

def score(self, query_tokens, doc_idx): qfreq = Counter(query_tokens) # 查询去重记数 dl = self.doc_len[doc_idx] # ① 查长度账 df = self.doc_freqs[doc_idx] # ② 取这篇词频账 score = 0.0 for term, qtf in qfreq.items(): if term not in df: # ③ 翻不到 → 跳过 continue tf = df[term] # ④ 翻到 → 次数 denom = tf + self.k1*(1-self.b + self.b*dl/self.avgdl) score += self.idf[term] * tf*(self.k1+1)/denom * qtf return score

注意 ③：continue 不是扣分，是贡献 0 分直接跳过。所以一篇不含任何查询词的文档，循环走完总分仍是 0.0。

四个查账动作 · 逐条对照

① 查长度账doc_len[doc_idx]
列表下标取值，O(1)。拿到 dl，准备和 avgdl 比长短。
② 取词频账doc_freqs[doc_idx]
拿到这篇文档专属的 Counter 对象，一个"词 → 次数"的字典。
③ 翻一页term not in df
字典成员判断，O(1)。翻不到这页 → continue，这个词 0 分。
④ 查身份证idf[term] · df[term]
两次字典取值：稀有度分 × 出现次数，代入公式累加。
03

公式对照：每个部件来自哪本账

查询期唯一用到的公式。颜色与三本账一一对应，k1=1.5 控制"重复收益递减"，b=0.75 控制长度惩罚强度。

score(q, d) = Σt ∈ q idf(t) × tf · (k₁ + 1)tf + k₁ · (1 − b + b · dl / avgdl) × qtf 查询期打分公式 · 对查询里的每个去重词元 t 累加
部件来源本例取值作用
idf(t)🪪 身份证册向量 0.981 / 检索 0.134越稀有越值钱，决定权重基调
tf📒 词频账命中词均为 1出现越多分越高，但饱和递减
dl / avgdl📏 长度账D0 1.29 · D1/D2 0.86比平均长 → 打折；比平均短 → 加成
qtf查询自身本例均为 1查询里重复出现的词额外加权
k₁=1.5, b=0.75构造期固定—经验值：饱和速度 / 长度惩罚强度

分子分母同时出现 tf，所以 tf→∞ 时该词贡献趋近 idf(t)·(k₁+1)/k₁ 上限——这就是"重复收益递减"：第 1 次出现最值钱，之后越来越不值。

D0 的 0.99 分里 88% 来自"向量"这一个词——它是 D0 独有的稀有词。而"检索"三篇都有、毫无区分度，几乎不改变排名。这就是 IDF 的直觉：决定排名的是稀有词，常见词只提供基础分。

05

细节放大：同一个词，D0 和 D1 得分为何不同

"检索"在两篇文档里 tf 都是 1，但贡献一个是 0.12、一个是 0.14——差别全在长度账。

D0（dl=3 > avgdl=2.33，比平均长 29%）
denom = 1 + 1.5×(1−0.75 + 0.75×3/2.33)
       = 1 + 1.5×1.214 = 2.82
贡献 = 0.134 × 2.5 / 2.82 = 0.12（打折）

D1（dl=2 < avgdl=2.33，比平均短 14%）
denom = 1 + 1.5×(1−0.75 + 0.75×2/2.33)
       = 1 + 1.5×0.893 = 2.34
贡献 = 0.134 × 2.5 / 2.34 = 0.14（加成）

为什么这么设计

假设没有长度项（b=0），公式退化成 idf × (k₁+1)/(k₁+1) × 常数——一个词在 500 词长文里的 1 次出现，和在一句话里的 1 次出现拿同样的分。但直觉上：短文档里命中，更说明整篇都在讲这件事。

b=0.75 表示"四分之三的程度"按长度修正：dl=avgdl 时分母恰好是 1+k₁×1，不长不短不奖不罚；dl 越大惩罚越重，dl 越小加成越多（但受 tf 饱和限制，不会无限放大）。

极端校准：b=0 完全忽略长度；b=1 完全按长度线性缩放。0.75 是多年经验默认值。

06

退一层看外层：分数数组怎么变成候选

score() 只回答"一篇文档多少分"。把 N 篇都问一遍、排序、截断，才是 BM25 一侧的完整产出。

# retriever.py · _bm25_scores def _bm25_scores(self, query_text): qtok = tokenize(query_text) return [self.bm25.score(qtok, i) for i in range(len(self.documents))] # retrieve() 中使用 bm25 = self._bm25_scores(query) bm25_order = sorted(range(n), key=lambda i: bm25[i], reverse=True)[:k]
本例的分数数组
bm25 = [0.99, 0.14, 0.14]

排序取前 k=20（不足全取）
bm25_order = [D0, D1, D2]

交给 RRF 融合
D0 得 1/(60+1) = 0.0164
D1 得 1/(60+2) = 0.0161
再叠加向量检索一侧的名次分

两个细节：查询文本也过同一个 tokenize，保证两边账本口径一致（同一套切词规则）；RRF 只看名次不看分值，所以 BM25 分数的绝对大小在融合时被丢弃，只留下先后顺序。
